# attune-companion

attune-companion 是连接 DeepSeek Harness（DSH）与 Attune 云端记忆引擎的开源插件。它的目标是让玩家在熟悉的聊天界面里管理自己的角色，在更换受支持的语言模型（LLM）后，仍能带着同一份角色设定和记忆继续聊。项目处于 MVP 设计阶段，以下描述的是首版目标。

比如，你曾告诉一个角色：“面试前别给我打气，先陪我练一道题。”几周后，你在新会话里说“明天又有面试了”，希望它还知道该怎么陪你。如果今天你说“这次我想听点鼓励”，它也应该听懂“这次”，保留你对下次的选择。

## 插件、云端引擎和 DSH 各负责什么

| 部分 | 职责 |
| --- | --- |
| attune-companion 开源插件 | 在客户端导入角色，说明哪些对话内容会发送到云端，让玩家按角色开启或关闭同步。提供查看、纠正、遗忘和导出记忆的入口。本仓库的开放范围包括插件、角色包格式和接入示例。 |
| Attune 云端引擎 | 作为独立托管服务，按账户和角色保存授权同步的设定与记忆，记录来源，处理纠正和删除。每轮根据当前话题和可用上下文长度，返回相关记忆、角色设定和近期进度。 |
| DSH 宿主 | 提供聊天界面和模型配置。插件把云端返回的内容交给宿主，宿主使用玩家配置的模型和 API 凭据发起请求，显示回复。 |

开启同步后，插件会把当前问题和必要的近期对话发给 Attune，以便检索；一轮对话结束后，再提交获准保存的内容。最终生成回复的模型会收到本轮选入的上下文。首版将检查宿主实际发送的请求，以验证长对话中的输入预算。[DeepSeek 多轮对话文档](https://api-docs.deepseek.com/guides/multi_round_chat/)

已有的 `ajuwm/dsh-roleplay-plugin` 提供了 DSH 角色扮演的实现参考。attune-companion 会借鉴它在长对话中保持角色风格、在新会话中恢复场景的做法。首版通过 DSH 适配器验证这些能力，角色与记忆包采用单独定义的格式，方便其他客户端实现导入和导出。[DSH 社区角色扮演插件](https://github.com/ajuwm/dsh-roleplay-plugin)

## 换一个 LLM，怎样继续聊

每个角色使用独立于模型和客户端的角色 ID。假设你在模型 A 里和角色约好“下次从面试自我介绍开始”，换模型后的续聊流程如下。

1. 在已接入 Attune 的客户端打开**同一账户下的原角色**，将聊天模型切换为客户端支持的模型 B。
2. 你发出“接着练吧”时，插件仍按原角色 ID 向 Attune 请求上下文。云端返回这个角色的设定、仍有效的偏好，以及上次约好的练习进度。
3. 客户端把这些内容连同当前消息发给模型 B，模型 B 就有依据从自我介绍接起。不同模型对同一句角色设定的演绎可能不同，措辞和语气会有差异。

如果同时更换客户端，新客户端需要支持连接 Attune，或能导入导出的角色包。使用本地角色包时，能恢复的内容以导出时保存的版本为准。直接打开模型厂商的普通聊天网页，也需要相应的接入或导入功能才能沿用这份记忆。

## 第一版要做什么

1. **带入已有角色。** 玩家可以粘贴长提示词，保留原文，选出必须保留的语气、边界和对话示例，再试聊确认。命理风格可以作为可选的角色创作素材，由玩家决定是否采用。关于玩家本人的记忆以其实际表达为依据。
2. **在新会话里接着聊。** 每个角色有独立的记忆范围。云端引擎组织本轮所需的设定和记忆，并区分玩家的现实经历与虚构剧情。找不到依据时，角色可以询问玩家。
3. **查看、纠正和遗忘。** 玩家可以从一条记忆查看它来自哪句话，改正误解，或要求忘记。修改应从下一轮生效，重启后仍然有效，旧摘要也应随之更新。
4. **导出和恢复。** 玩家可以把角色版本、有效记忆、必要的来源片段和近期进度导出为带格式版本号的本地文件，并在新的环境中恢复。恢复的是这些可检查的内容，具体回复仍会随模型和设置变化。

## 怎样算首版完成

首版验收会使用一份可公开分发的示例角色卡。在 DSH 用模型 A 聊出一个偏好，纠正它，再约好下次的话题。随后打开新会话，切换到另一个受支持的模型，检查它能否接上话题、采用修正后的偏好，并比较实际发送的输入 token 数。最后把导出的角色包交给示例客户端，单独验证从文件恢复的过程。
